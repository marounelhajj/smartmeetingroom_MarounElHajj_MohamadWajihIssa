Rooms Service¶

Database Model¶

The Rooms Service manages meeting rooms in the rooms table.

Table: rooms

Column

Description

id

Integer primary key

name

Unique room name

capacity

Maximum number of people

equipment

Comma-separated equipment list

location

Building / floor / campus

is_available

Boolean flag for availability

created_at

UTC timestamp of creation

Authentication¶

Most endpoints in the Rooms Service require a valid JWT token generated by the Users Service.

  • The token is expected in the Authorization header:

    Authorization: Bearer <token>

  • A small helper (decode_token) verifies the token and extracts:

    • user id

    • role

  • @auth_required checks that the token is valid.

  • @admin_or_facility_required additionally checks that the role is admin or facility_manager.

Typical Usage¶

  1. Create a room (admin / facility only):

    • POST /api/rooms with JSON body:

      {
  "name": "Conference Room A",
  "capacity": 10,
  "equipment": "Projector, TV",
  "location": "Building 1, Floor 2",
  "is_available": true
}

  2. List rooms (no auth required):

    • GET /api/rooms?min_capacity=8&available=true

  3. Get a single room:

    • GET /api/rooms/1

  4. Modify a room (admin / facility only):

    • PUT /api/rooms/1 with any subset of fields.

  5. Delete a room (admin / facility only):

    • DELETE /api/rooms/1

Filtering¶

The GET /api/rooms endpoint supports several optional query parameters:

  • min_capacity – integer filter on capacity.

  • location – case-insensitive substring search.

  • equipment – case-insensitive substring search.

  • available – true / false / 1 / 0.
